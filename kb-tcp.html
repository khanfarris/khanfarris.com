NOTE 19 / Networking

TCP_

Concept Concept study

IN PLAIN ENGLISH

TCP carries an ordered stream of bytes between two endpoints. It tracks delivery and retransmits missing data so applications do not have to handle ordinary packet loss themselves.

Identify the two ends

A TCP connection has a source IP and port and a destination IP and port. For example, a laptop at 10.0.0.25:53010 might connect to a web service at 192.0.2.80:443. The client commonly chooses a temporary, or ephemeral, source port. Replies reverse the source and destination. The documentation address here represents a fictional server.

Two connections to the same server can use different client ports. A browser tab does not map neatly to one TCP connection: requests may share a connection or use several. HTTP/2 can carry multiple request streams over one TCP connection.

Open, transfer, and close

  1. SYN → SYN-ACK → ACK: the usual three-way handshake establishes a connection and synchronizes initial sequence numbers.
  2. Data and acknowledgements: the sender transmits bytes and the receiver indicates what it has received.
  3. Retransmission: missing data can be sent again. Flow control limits data to what the receiver can handle; congestion control responds to network conditions.
  4. FIN / ACK or RST: a connection can close in an orderly way or be reset. Interpret the surrounding packets before deciding why.

Sequence number versus conversation number

A TCP sequence number identifies a position in the byte stream. If a segment starts at sequence 1000 and carries 100 data bytes, the next data byte would normally be sequence 1100. An acknowledgement generally identifies the next byte expected. SYN and FIN each consume sequence-number space too.

Wireshark’s tcp.stream is different: it is an analysis index identifying a conversation within a capture. It is not transmitted in the TCP header. The stream index helps you select a conversation; sequence numbers help you follow the bytes inside it.

Why the header length is a multiple of four

A TCP header starts with a fixed 20-byte part. Optional fields can make it longer. Its Data Offset field stores the total header length in units of four bytes, called 32-bit words. A value of 5 means 20 bytes; 8 means 32 bytes. The receiver uses that length to find where application data begins.

INTERACTIVE / FICTIONAL EXAMPLE

Find where the payload begins

Change the number of option bytes. See how padding makes the total TCP header fit the four-byte units used by Data Offset.

A No-Operation option is one byte and can align options. End-of-option-list padding can also fill remaining header space. The “packing peanuts” analogy is about alignment, not adding application data. For a simple 20-byte base plus 10 bytes of options, two more bytes make a 32-byte header.

Use it during troubleshooting

No reply to SYN can indicate filtering, routing, an unavailable host, or capture limitations. A reset can indicate refusal or a closed connection, but inspect its source and timing. Repeated retransmissions can suggest loss or missing capture visibility. TCP itself does not provide encryption; TLS supplies protection for many applications.

PUT IT INTO WORDS

Check your understanding

A TCP segment starts at sequence 1000 and carries 100 data bytes. Is tcp.stream == 1100 the way to find the next bytes?

Show an example answer

No. Sequence 1100 would describe the next data-byte position in this simplified example. tcp.stream is Wireshark’s separate identifier for the whole connection. Filter the right stream, then inspect sequence and acknowledgement numbers inside it.
