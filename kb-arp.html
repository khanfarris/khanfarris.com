NOTE 05 / Networking

ARP_

Concept Concept study

IN PLAIN ENGLISH

ARP finds the MAC address needed to deliver IPv4 traffic to the next device on a local network. For a remote destination, that device is usually your gateway.

Why an IP address is not enough

Your laptop wants to send data to a printer. It knows the printer’s IPv4 address, but an Ethernet network delivers local traffic using MAC addresses. A MAC address identifies a network interface on that link, often written as six hexadecimal pairs, such as 02:00:00:00:00:50. It is different from the IP address and is not a permanent proof of device identity.

An IP packet carries the network-layer destination. For its trip across an Ethernet link, that packet sits inside a frame with local source and destination MAC addresses. Address Resolution Protocol (ARP) supplies the missing IPv4-to-MAC mapping for the next hop: the device that should receive this frame.

Ask the local network, then remember the reply

Imagine a laptop at 10.20.10.25/24 and a printer at 10.20.10.50/24, both on the same VLAN.

  1. The laptop checks its routing information. In this simple network, the printer is directly reachable on the local subnet.
  2. It checks its ARP cache, a temporary table of IP-to-MAC mappings. A usable entry can avoid a new request.
  3. Without an entry, it broadcasts an ARP request: “Who has 10.20.10.50? Tell 10.20.10.25.” The Ethernet destination is ff:ff:ff:ff:ff:ff, the broadcast address. The switch distributes it within that VLAN.
  4. The printer normally replies directly to the laptop with its MAC address. The laptop caches the mapping and can address the frame to the printer.

Other devices can hear the request, but they do not normally answer for an address they do not own. ARP itself runs directly over the local link; it does not use a TCP or UDP port.

What changes when the destination is remote?

Now the laptop wants to reach a website outside its subnet. With a default route through 10.20.10.1, it resolves the gateway’s MAC address. It does not broadcast across the internet asking for the website’s MAC.

The frame is addressed to the gateway, while the packet inside still names the website’s IP as its destination. The router removes the incoming link-layer framing and forwards the packet using the next link’s addressing. Ordinary ARP broadcasts do not pass through routers. This is why understanding the subnet and gateway comes before interpreting an ARP lookup.

INTERACTIVE / FICTIONAL EXAMPLE

Who should answer?

Choose a printer or a remote website. Follow the lookup, request, reply, and first frame. Send again to see what the cache changes.

Keep the different tables straight

MechanismQuestion it answers
DHCPWhich IP configuration should this device use?
DNSWhat address is associated with this name?
Routing tableWhich next hop and interface should carry this IP packet?
ARP cacheWhich MAC address corresponds to that local IPv4 next hop?
Switch MAC tableWhich switch port leads toward this MAC address in this VLAN?

Use it on a connectivity ticket

A laptop has a valid address but cannot reach the gateway. Check its address, mask, gateway, and VLAN first. On Windows, arp -a displays cached mappings, separated by interface. Compare the relevant next-hop entry with the expected device, and inspect a capture with Wireshark’s arp display filter if needed.

Repeated requests without replies can suggest an offline next hop, wrong VLAN, incorrect addressing, or a filtering/link problem. Check the capture location too. A MAC entry proves neither that the application works nor that its IP owner is authentic. Record evidence before clearing a cache; “delete everything and retry” can hide a useful clue.

Address changes and security

Dynamic entries age or are refreshed according to the operating system. Devices can also announce an address mapping without first receiving an ordinary request, often called gratuitous ARP. ARP probes and announcements support address-conflict detection and legitimate changes such as failover, so a mapping change is not automatically an attack.

ARP does not authenticate ownership of an address. False mappings, called ARP spoofing or cache poisoning, can redirect or disrupt local traffic. Investigate unexpected gateway mappings alongside device and switch evidence. On supported switches, Dynamic ARP Inspection validates ARP information against trusted bindings, commonly learned through DHCP snooping; static devices and trusted ports need appropriate configuration.

Scope to remember

This note describes ordinary IPv4 over Ethernet. Proxy ARP is a special case where a router answers on another device’s behalf. IPv6 uses Neighbor Discovery rather than ARP.

PUT IT INTO WORDS

Check your understanding

Your laptop sends to a website outside its /24 subnet. Does ARP look up the website’s MAC address or the default gateway’s, and which IP remains inside the packet?

Show an example answer

With the default route selected, ARP resolves the gateway’s local IPv4 address to its MAC. The Ethernet frame goes to that gateway, while the enclosed IP packet still names the website as its destination. A usable cached gateway mapping can avoid a new ARP request.
