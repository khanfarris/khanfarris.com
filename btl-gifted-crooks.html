STARTING POINT

Understand the event before counting anything

MISP is a platform for organizing and sharing threat intelligence. An event collects information about a threat or investigation. Its attributes are individual pieces of information, such as a filename, hash, IP address, or report link. An object groups related attributes so their relationship is clear.

I opened event 10128 in the lab's MISP interface. I started with the summary at the top, then moved into the attributes below it. An indicator of compromise (IOC) is an observable value that can help an analyst look for suspicious activity. Finding an IOC in an intelligence record does not mean my own computer contacted it.

  1. HeaderWho published it, when, and how it is tagged.
  2. AttributesRead each value with its type and category.
  3. ObjectsKeep a file with its hashes, or an IP with its port.
  4. ContextUse comments and the original report to explain the values.

Platform reference: MISP user guide.

The #Attributes row already gives both totals, so there is no need to count every visible line.

An attribute is a single value with a type and category, such as an IP address. An object groups related attributes. For example, a file object can hold its filename, MD5, and SHA-256 together. Those hashes are fingerprints of the file’s contents, not extra files.

QUESTION 09

According to this event, A C2 was established. What is the first IP and Port used by the adversary? Use the defanged IP recipe by CyberChef.

C2 means command and control: communication that lets an attacker direct compromised software. The standalone IP attributes have C2 in their comments. I matched the requested IP to its own ip-port object, where ip-dst identifies the destination address and dst-port gives its port.

Answer

89[.]44[.]9[.]186, 3240

Defanging means writing an indicator in a form less likely to become an accidental clickable link: dots become [.]. In CyberChef, add Defang IP Addresses and enter the IP to make that change. CyberChef transforms text; it does not decide whether the IP is malicious.

“First” is the lab’s label here. The position of a row on screen does not prove which server was used first.

QUESTION 10

What is the second IP and Port used by the adversary in this campaign? Use the defanged IP recipe by CyberChef.

I found the separate object for 37[.]120[.]239[.]187 and read its own destination port: 6501. I did not borrow port 3240 from the nearby object.

Answer

37[.]120[.]239[.]187:6501

The border matters: an object ends at its enclosing border. Standalone rows below it do not inherit its port. The separate 149[.]102[.]246[.]110 row is labelled VPN, so it is not one of these two C2 answers.

CHECK MY UNDERSTANDING

Questions to revisit

How do I know which port belongs to an IP?

I read the destination IP and port inside the same object. A nearby standalone IP row is a separate attribute and does not inherit the port above it.

Why can the attribute count be larger than the file count?

One file can have several attributes, including its filename and multiple hashes. I count unique file records when the question asks for files.

Does an IP's country identify the attacker?

No. Registry information describes the registration of network resources. Hosting, VPNs, and proxies can separate infrastructure from the person operating it.

Does clicking a MISP tag explain its meaning?

Not necessarily. A tag can filter related events without providing a definition. I use the source organization or the published standard to confirm what it means.

Recap

I learned to read a MISP event as related evidence instead of a list of answers. I checked the header for context, kept attributes inside their objects, separated filenames from hashes, and used source material when a value needed explanation. The main habit I want to keep is asking what a field proves before deciding what it means.
