NOTE 15 / Cloud & telemetry

Azure NSGs: policy along the path_

Study basis: Lab application

THE PRINCIPLE

Cloud network rules and the guest operating system's firewall are separate enforcement points.

THE CONNECTION

The honeypot lab changed both an Azure NSG and Windows Firewall. Opening one layer does not automatically change the other.

Identify what an NSG controls

An Azure Network Security Group filters network traffic using rules that include source, destination, ports, protocol, direction, priority, and action. Rules apply through associations such as a subnet or network interface. A rule's presence is not enough: the association and traffic path determine whether it is relevant.

NSGs are stateful. Allowed connection state affects return traffic; a rule change should not be assumed to terminate every already-established connection. Rule priority and existing state matter when verifying behavior.

Follow inbound and outbound evaluation

Where both associations exist, inbound traffic is evaluated at the subnet NSG and then the NIC NSG. Outbound traffic is evaluated at the NIC NSG and then the subnet NSG. Each applicable enforcement point must permit the flow. Routes determine where packets travel; NSG rules filter traffic on that path.

Inbound path→Subnet NSG→NIC NSG→Guest firewall + service

Connect the two firewalls

Windows Firewall runs in the guest operating system. It can block a connection that the cloud-side rules permit. Conversely, allowing a Windows Firewall rule cannot override a denying NSG. A listening application is another requirement; firewall permission does not start a service.

The study lab intentionally exposed a honeypot to observe unsolicited connection attempts. That exposure was a property of the experiment, not a suitable baseline for an ordinary production VM. Production rules should permit the required sources and services rather than reproduce the lab's broad exposure.

Verify the actual flow

Identify the source and destination addresses, ports, protocol, direction, effective rules, and route. Check the guest firewall and service state. An NSG is not limited to traffic arriving directly from the public internet; its applicable associations and rules also matter for other network paths.

CLOSE THE NOTES. MAKE THE CONNECTION.

Recall check

An NSG permits the intended connection, but it still fails. What remains to check?

Reveal the reasoning

Other applicable NSGs, routing, the guest firewall, and the listening service. An allow at one point does not establish an end-to-end permitted and working path.
