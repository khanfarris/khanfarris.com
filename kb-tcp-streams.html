Wireshark_

Tool guide Tool study

IN PLAIN ENGLISH

Wireshark lets you inspect a packet capture, filter the traffic you see, and follow individual conversations. Its three main panes show packets, decoded fields, and the corresponding bytes.

This guide focuses on using the interface. Read TCP for handshakes, sequence numbers, ports, and header padding. Use only captures you are authorized to inspect; the examples here use fictional values.

Navigate the three panes

PaneWhat to do there
Packet list, usually at the topSelect a packet. Columns show time, source, destination, protocol, length, and a short summary.
Packet details, usually in the middleExpand protocol sections such as Ethernet, IP, and TCP. Select a field to inspect its decoded value.
Packet bytes, usually at the bottomSee the selected packet’s hexadecimal bytes and printable characters. Selecting a decoded field highlights its corresponding bytes.

Use display filters to narrow the view

ip.addr == 10.0.0.25
tcp.port == 443
tcp.stream == 3
dns
tcp.flags.syn == 1 && tcp.flags.ack == 0

These filters show traffic involving an IP, TCP traffic using a port, one TCP conversation, DNS traffic decoded as DNS, or initial SYN packets. A display filter hides unrelated captured packets from the view. A capture filter controls what is recorded in the first place and uses a different syntax. A display filter cannot recover packets that were never captured.

Follow one conversation

  1. Select a packet belonging to the connection of interest.
  2. Use the context menu or Analyze menu to choose Follow → TCP Stream.
  3. Inspect the conversation and its two directions. Encrypted TLS application traffic is not readable plaintext merely because you followed the TCP stream.
  4. Return to the packet list and inspect timing, resets, retransmissions, and decoded fields in context.
  5. Check or clear the active display filter before moving to a different investigation.

Stream 3 means the conversation Wireshark indexed as 3 in this capture, not packet 3 or byte 3. Do not assume the same number identifies the same conversation in another capture. Use addresses, ports, and timestamps when documenting it.

Read the bytes without guessing

The numbers along the left of the bytes pane are offsets: positions counted from the beginning of the displayed byte source, starting at zero. Hexadecimal uses digits 0–9 and A–F. 0x16 equals 1 × 16 + 6 = 22, and 0x80 equals 8 × 16 = 128. The 0x prefix indicates hexadecimal notation.

An offset is a position, while a byte value is the data at that position. They are not automatically related. Instead of assuming TCP starts at a particular fixed offset, expand TCP and select Header Length or another decoded field. Wireshark highlights where that field actually appears in this packet, accounting for the headers before it.

Export a useful finding

Record the capture name, packet numbers, timestamps, addresses, ports, filter, and observed behavior. Use Statistics → Conversations for an overview of participating endpoints, and Expert Information for items worth inspecting. Expert warnings are analysis hints, not automatic proof of malicious activity. Packet captures can omit traffic because of capture location or loss, so describe what was observed rather than claiming complete visibility.

PUT IT INTO WORDS

Check your understanding

What is the difference between offset 0x16 and a byte with value 0x80 in the packet bytes pane?

Show an example answer

Offset 0x16 is a position 22 bytes from the beginning of the displayed byte source. A byte value of 0x80 represents the number 128 at its position. Select the corresponding decoded field to learn what those bytes mean in the protocol.

TCP ↗

TCP carries an ordered stream of bytes between two endpoints. It tracks delivery and retransmits missing data so applications do not have to handle ordinary packet loss themselves.

TLS ↗

TLS protects data in transit by encrypting it and checking that it has not been changed. In a normal HTTPS connection, it also helps the browser verify the server’s identity.
