NOTE 09 / Identity & access

Timus: access to a resource_

Study basis: Concept study

THE PRINCIPLE

Network reachability, authentication, and authorization are separate checks in an access decision.

THE CONNECTION

A home PC cannot automatically browse another PC's files simply because both share a network. That distinction explains why a VPN, ZTNA, and a virtual desktop are different.

Start with the resource

Zero Trust Network Access evaluates access to protected resources using policy and identity context. Timus provides ZTNA capabilities. The useful question is which user and device may reach which resource under which conditions, rather than whether a user is simply “inside” a trusted network.

An agent can participate in enforcing connectivity and device-related policy. Its presence does not make it equivalent to an EDR agent: an access product and an endpoint response product have different primary responsibilities.

Three gates to a file share

  1. Reachability: a permitted network path to the file service exists.
  2. Authentication: the service establishes the connecting identity.
  3. Authorization: that identity has permission to the requested content.

A VPN can provide a network path without granting file permissions. VPNs can also be segmented and constrained; they do not inherently provide unrestricted access to everything. ZTNA emphasizes policy-controlled access rather than relying on broad network membership.

Connect the virtual-desktop comparison

A Citrix-style virtual desktop runs a desktop or application remotely and presents it to the user. ZTNA controls access to resources; it does not inherently move the user's desktop into a remote environment. The technologies can coexist.

A virtual desktop does not make an untrusted local device harmless. Session theft, captured keystrokes, screenshots, and enabled redirection remain relevant considerations. “The application runs remotely” is a statement about execution location, not a complete security guarantee.

Where Conditional Access fits

Microsoft Entra Conditional Access evaluates identity-related access conditions for supported resources. A Conditional Access policy alone does not create an arbitrary network path to an internal SMB server. Entra Private Access can extend identity-based controls to private resources, so the distinction should be made by architecture rather than a permanent “cloud versus network” divide.

This is conceptual access-model study; no Timus policy deployment is represented here.

CLOSE THE NOTES. MAKE THE CONNECTION.

Recall check

If a user connects through an approved access service, must a file share open?

Reveal the reasoning

No. The resource must be reachable, the identity must authenticate, and the share and underlying file permissions must authorize access.
