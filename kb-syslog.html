NOTE 07 / Cloud & telemetry

Syslog_

Concept Concept study

IN PLAIN ENGLISH

Syslog is a common way for devices and applications to send event messages to a central place. Instead of opening every firewall or server, an analyst can review their messages together.

Start with one event

A switch port goes down. A firewall blocks a connection. A Linux service fails to start. Each system can write a message describing what happened. With syslog forwarding configured, it also sends that message to a collector: a server that receives logs from other systems.

A log is a recorded event. A collector stores or forwards those events. A SIEM can search and analyze collected events and create alerts using rules. Receiving a syslog message does not automatically mean an attack was detected.

Read the message in pieces

<134>1 2026-09-05T10:15:00Z fw-01 firewall 812 DENY - Blocked TCP from 10.20.10.25 to 10.20.30.10:445

This fictional RFC 5424-style message records one blocked connection. fw-01 identifies the reporting device; the timestamp says when it recorded the event. The final text explains the action, source, and destination. 445 is a service port commonly used for SMB file sharing.

INTERACTIVE / FICTIONAL EXAMPLE

Which messages reach the collector?

Change the forwarding threshold. Lower severity numbers are more urgent; the word “blocked” does not automatically mean “critical.”

Severity is a label, not a verdict

Syslog has eight severity levels: 0 emergency, 1 alert, 2 critical, 3 error, 4 warning, 5 notice, 6 informational, and 7 debug. The sender assigns a level. A normal firewall deny can be informational. An informational event can still matter to an investigation. If a device forwards only warning and more urgent messages, levels 5–7 may never reach the collector.

How the messages travel

The device needs a destination collector address, a transport and port, and a choice of messages to forward. Traditional UDP syslog commonly uses port 514. UDP provides no delivery acknowledgement, so messages can be lost. Syslog over TLS commonly uses TCP 6514 to protect the connection. Plain TCP alone does not encrypt the messages; the sender and receiver must support and agree on the chosen transport.

Use it in an investigation

Suppose a user cannot reach a file server. Search the firewall’s collected events for the user’s source IP, the server’s destination IP, port 445, and the time of the attempt. A matching deny can identify the rule that blocked it. Record the rule and intended access before changing it.

If no message appears, check whether the device generated it locally, whether its forwarding filter includes that severity, and whether the collector is receiving other events. Then check parsing, timestamps, and the search time range. “No results” can mean missing collection or a wrong query, not “nothing happened.”

PUT IT INTO WORDS

Check your understanding

A firewall shows a local informational deny event, but the collector only receives warning and more urgent events. Why is your search empty?

Show an example answer

Informational is severity 6; warning is 4. A threshold that includes only 0–4 excludes that deny. Check the forwarding filter and collection path before concluding that the event did not happen. The sender’s severity is not an analyst’s final threat assessment.
