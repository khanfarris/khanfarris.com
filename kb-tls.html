NOTE 18 / Networking

TLS_

Concept Concept study

IN PLAIN ENGLISH

TLS protects data in transit by encrypting it and checking that it has not been changed. In a normal HTTPS connection, it also helps the browser verify the server’s identity.

Put it in a web connection

When you use https://, the browser uses HTTP with TLS protection. HTTP describes the web request and response. TLS, Transport Layer Security, protects the exchanged data. TCP commonly provides reliable delivery for HTTP/1.1 and HTTP/2, while IP carries packets between network addresses. HTTP/3 uses QUIC over UDP and incorporates TLS 1.3.

Plain HTTP commonly uses TCP too. TCP gives ordered delivery and recovery from loss; it does not encrypt the application’s contents. Adding encryption is not the same as changing whether traffic uses IP.

What happens during the handshake?

  1. The client and server agree on supported TLS parameters.
  2. The server presents a certificate. The client checks the requested hostname, validity, and trust chain under its validation rules.
  3. They establish shared session keys using the negotiated handshake.
  4. Application data then travels in protected records that provide confidentiality and integrity.

A certificate links an identity, commonly a hostname, to a public key through a trust system. It is not a promise that the business is honest. A malicious website can have a valid certificate for its own domain.

Keep the security promises precise

PropertyMeaning
ConfidentialityA passive observer should not be able to read protected application contents.
IntegrityTampering with protected records should be detected.
AuthenticationThe client verifies the server’s identity through certificate validation in a typical HTTPS connection. Client certificates are optional in ordinary web use.
LimitsTLS does not stop a compromised endpoint from reading its own plaintext or make a harmful website safe. Some traffic metadata remains visible.

Versions and certificates

TLS 1.3 is the modern protocol version. TLS 1.2 can still be secure with appropriate algorithms and configuration; it is not automatically broken just because 1.3 exists. Older SSL and TLS versions should not be used as a workaround. A failed certificate check can indicate an expired certificate, wrong hostname, untrusted issuer, incorrect system time, or authorized or unauthorized interception.

Use it on an application ticket

A service can answer on TCP 443 while TLS or the application still fails. Record the exact browser or client error and affected hostname. Check the certificate’s subject names, dates, trust chain, and the device’s clock. Compare another device and network path, including any proxy or security inspection. Do not teach the user to ignore certificate warnings as a routine fix.

One boundary at a time

A successful DNS lookup finds the address. A TCP test checks transport reachability. A successful TLS handshake checks the negotiated protected channel. The application still has to respond correctly.

PUT IT INTO WORDS

Check your understanding

A site has a valid HTTPS certificate. Does that mean the site’s content is trustworthy?

Show an example answer

No. A valid certificate helps authenticate the connection to that hostname and protect data in transit. An attacker can obtain a valid certificate for a domain they control, and a legitimate site can also be compromised.
