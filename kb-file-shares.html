NOTE 16 / Identity & access

File shares_

Concept Concept study

IN PLAIN ENGLISH

A file share lets other computers access a folder over the network. The network path finds the server and share; the user’s permissions decide what they can do there.

Read the path

\\files-01\Finance
Z:  →  \\files-01\Finance

A path beginning with two backslashes is a UNC path. files-01 is the server name and Finance is the share name. A mapped drive such as Z: is a convenient local shortcut to that path. Losing the drive letter does not necessarily mean the files or server disappeared.

A file server can be a general-purpose server offering folders. A NAS, or network-attached storage device, is a storage-focused appliance that can also offer shares. Both may provide SMB, the file-sharing protocol commonly used by Windows. Modern direct SMB commonly uses TCP port 445.

Four things must work

  1. Name: the computer resolves the server name to the intended address.
  2. Path: the network and any approved remote-access service can reach the server’s SMB service.
  3. Identity: the server authenticates the account being used.
  4. Permission: the account is authorized to use the share and the requested files.

Being on the same network or connected through a VPN does not expose every person’s files automatically. A folder must be shared and permissions must allow the requested access. The same applies when an access service permits the network connection.

Share permissions and file permissions

Windows file access over a share is constrained by both the share’s permissions and the file system’s permissions, commonly NTFS permissions. Allowing Modify on the share does not override a file permission that prevents the write. Use effective-access tools and the actual group memberships when troubleshooting; inherited permissions and deny entries can make a quick glance misleading.

Troubleshoot a missing mapped drive

  1. Record the drive letter, expected UNC path, user, error, and whether other users are affected.
  2. Try the known UNC path. If it works, investigate the mapping or its deployment policy.
  3. If the name fails, check DNS and the remote-access path. A service-port test can help separate reachability from authorization.
  4. If the share opens but writing fails, check the exact account, share permissions, file permissions, and storage state.
  5. If everyone is affected, inspect server and service health, disk space, and recent changes.
Resolve-DnsName files-01
Test-NetConnection files-01 -Port 445
Get-SmbMapping

These Windows checks inspect name resolution, a TCP connection, and existing drive mappings. Substitute the actual server. A successful TCP check does not prove the user can authenticate or read a folder. Avoid granting broad access as a shortcut; restore the intended access for the affected group.
