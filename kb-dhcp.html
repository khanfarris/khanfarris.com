NOTE 07 / Networking

DHCP_

Concept Concept study

IN PLAIN ENGLISH

DHCP automatically gives a device an IP address and the network settings it needs. The address is borrowed for a lease period, rather than manually typed into every computer.

What a new laptop needs

When a laptop joins an office network, it needs an available IP address, a subnet mask, a default gateway for reaching other networks, and DNS servers for looking up names. Dynamic Host Configuration Protocol supplies these settings. A home router often runs the DHCP service, but a business may use Windows Server, a firewall, or another network service. DHCP is not limited to routers.

The first lease: DORA

  1. Discover: the client looks for a DHCP server. It does not yet have a usable lease for this network.
  2. Offer: a server offers an address and configuration.
  3. Request: the client requests the selected offer.
  4. Acknowledge: the server confirms the lease. The client can apply the settings after its normal checks.

Read a DHCP scope

SettingExample and purpose
ScopeThe address pool and settings for one subnet: 10.20.30.0/24.
PoolOffer 10.20.30.50–10.20.30.200 to clients.
ExclusionKeep statically configured devices out of the offered pool.
ReservationGive a particular client a consistent address through DHCP, commonly identified by its MAC address or client identifier.
LeaseHow long the client may use the assignment before it expires unless renewed.
OptionsSupply the gateway and DNS servers. Option 003 is routers; 006 is DNS servers in common Windows DHCP administration.

A reservation still depends on DHCP. A manually configured static address is set on the device itself. Plan both so two devices are not assigned the same address.

Why VLANs sometimes need a relay

The first broadcast does not normally cross a router. If the DHCP server is on another subnet, a DHCP relay forwards the request and identifies the client’s network so the server can choose the right scope. A new VLAN may have perfectly good switch ports but no functioning DHCP path if its relay or scope is missing.

Troubleshoot “I have no network”

Start with ipconfig /all. Check whether DHCP is enabled, which server supplied the lease, the address, mask, gateway, DNS servers, and lease times. On a Windows client configured for DHCP, an unexpected 169.254.x.x link-local address is a clue that it could not obtain a lease. It is not proof of the exact failure.

Compare another device on the same VLAN. Check scope exhaustion, server health, relay settings, switch VLAN membership, and unexpected DHCP servers. A wrong DNS option can produce a valid IP but broken name lookups. Releasing an address can disconnect a remote-support session, so plan any renewal work around the user’s access.

PUT IT INTO WORDS

Check your understanding

Devices on one new VLAN get 169.254 addresses, while other VLANs work. What would you check?

Show an example answer

Confirm the clients are using DHCP and are on the intended VLAN. Check that VLAN’s scope, available addresses, gateway relay, and path to the DHCP server. A failure limited to one VLAN points toward its configuration or path, though the address alone does not prove the cause.
