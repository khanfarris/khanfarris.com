ARCHIVED / NOTE 01 / Identity & access

Microsoft 365_

Ecosystem guide Concept study

IN PLAIN ENGLISH

Microsoft 365 combines work applications with identity, device management, and security services. Entra identifies users, Intune manages devices, Defender investigates threats, and Conditional Access controls sign-ins.

Start with the employee’s workday

An employee opens Outlook, joins a Teams call, and edits a file in SharePoint. Those familiar applications rely on several systems underneath. Exchange Online hosts cloud email. SharePoint and OneDrive provide collaboration and file storage. Teams provides collaboration and uses other Microsoft 365 services for parts of its experience. The organization’s tenant is its instance of these cloud services.

Know which service answers which question

ServiceQuestion it helps answerCommon analyst use
Microsoft Entra IDWho is the user and how did they sign in?Review users, groups, sign-in logs, authentication methods, and risk where available. Azure AD is its former name.
Conditional AccessUnder what conditions may this user access this application?Inspect the actual policy result and requirements such as MFA or a compliant device. This is an Entra capability.
Microsoft IntuneHow is this device managed, configured, and evaluated?Check enrollment, last check-in, compliance findings, configuration, and app deployment.
Microsoft DefenderWhat threats or suspicious activity are detected?Investigate endpoint, email, identity, or cloud application evidence in the relevant Defender service.
Microsoft 365 admin centerIs a service, account, or license affecting the employee?Check service health, users, and licensed services before treating every outage as a security incident.

“Defender” is a family of products

Defender for Endpoint supplies endpoint investigation and response. Defender for Office 365 focuses on threats involving email and collaboration. Defender for Identity provides signals about supported identity environments, including AD DS. Defender for Cloud Apps provides cloud application security capabilities. Defender XDR connects signals from enabled products into investigations. A customer does not automatically have every component or feature.

INTERACTIVE / FICTIONAL EXAMPLE

Make an access decision

Try a SharePoint request: Conditional Access requires MFA and a compliant device; the files separately require Finance group membership. Change a signal and follow both decisions.

How the services work together

In this example, Intune evaluates whether a laptop satisfies configured device requirements. With the Defender for Endpoint integration configured, a device-risk signal can also influence Intune compliance. Entra’s Conditional Access policy can require that compliant status when the employee accesses SharePoint. A correct password is therefore not enough if another required condition fails.

A policy must actually target the request and require the control for the signal to affect access. Merely enrolling a device does not make every application require compliance. Detection, device evaluation, and access enforcement are separate configured pieces. The exercise models one Conditional Access policy plus a SharePoint group permission. Real requests may be evaluated by several applicable policies.

Work an “Outlook stopped working” ticket

  1. Check scope and Microsoft 365 service health. Record the user, application, device, time, and exact error.
  2. Review the relevant Entra sign-in and its Conditional Access results. Did authentication fail, or did a policy requirement fail?
  3. If device compliance caused the failure, inspect the device in Intune: enrollment, last check-in, and the specific failed setting.
  4. If a threat or account takeover is suspected, inspect the relevant Defender and service audit evidence. Intune is not a complete activity log for every cloud action.
  5. Correct the underlying issue through the approved process, then verify a new sign-in. Document which service supplied the evidence.
Access and licensing vary

Use the customer’s actual licenses, enabled integrations, and admin role to determine which screens and actions are available. Risk-based features and advanced investigation are not included in every Microsoft 365 plan.

PUT IT INTO WORDS

Check your understanding

A user knows their password and passes MFA but is blocked because their device is noncompliant. Which tools help you investigate?

Show an example answer

Use Entra sign-in logs to identify the Conditional Access policy and failed requirement. Use Intune to inspect that device’s compliance details and check-in state. If an integrated Defender device-risk signal is involved, investigate the threat there. Fix and verify the cause rather than broadly disabling the policy.
