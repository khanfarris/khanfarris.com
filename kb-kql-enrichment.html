NOTE 18 / Cloud & telemetry

KQL enrichment: match the schema_

Study basis: Lab application

THE PRINCIPLE

A lookup can only enrich events when the query references a real data source with the expected columns and compatible values.

THE CONNECTION

Changing from a watchlist to external CSV data did not automatically update the workbook's query. The missing network-column error exposed the dependency underneath the map.

Separate the event from the enrichment

The lab combined security events containing source IP addresses with a geolocation reference dataset. The event supplied the observed address; the reference data supplied an approximate location associated with an address range. The workbook visualized the query result.

The map template and geolocation reference were external inputs used in the lab. Their presence in a workbook did not make the template or dataset an original implementation.

Diagnose the missing column

An IPv4 range lookup needs an event-side address field and a reference-side range field. If the query names a column that is absent from the reference schema, the lookup cannot evaluate that relationship. Inspect the actual column names and types before copying or changing the lookup expression.

// Shape example: both table names and their columns must exist.
EventsWithIP
| evaluate ipv4_lookup(GeoRanges, SourceIP, Network)

Here EventsWithIP must expose SourceIP, and GeoRanges must expose compatible CIDR ranges in Network. These are illustrative names, not a ready-to-run query against every Sentinel workspace.

Update the consumer as well as the source

A workbook calling _GetWatchlist(...) still depends on that watchlist even if a separate query now uses externaldata. Verify the workbook's own query. Also distinguish JSON syntax errors in a workbook definition from KQL execution errors: they occur at different layers.

Inspect the source schema, test a small result, validate the lookup, and only then troubleshoot the visualization. Keep credentials and signed data-access URLs out of published examples.

Interpret the map conservatively

IP geolocation is an estimate associated with a network address. VPN exits, proxies, and hosting providers complicate attribution. A map marker does not identify a person's physical location or prove who initiated an attempt.

CLOSE THE NOTES. MAKE THE CONNECTION.

Recall check

The standalone enrichment query works, but the workbook still reports a missing watchlist. Why?

Reveal the reasoning

The workbook may still execute its original _GetWatchlist query. Check and update the consumer's data-source reference, then verify the columns it expects.
