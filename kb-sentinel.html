NOTE 16 / Cloud & telemetry

Sentinel: follow the event pipeline_

Study basis: Lab application

THE PRINCIPLE

Troubleshoot collection from the original event through the agent and collection rules to the queryable workspace.

THE CONNECTION

Checking Event Viewer still matters even when a connector is configured. It establishes whether the event exists before investigating its journey into Sentinel.

Follow one known event

In the Windows-event lab, the source was the VM's Windows event logging. Azure Monitor Agent and a Data Collection Rule defined a collection path into a Log Analytics workspace. Microsoft Sentinel used the connected workspace's security data for analysis.

Windows event→AMA + DCR→Log Analytics workspace→Sentinel analysis

Enabling Sentinel is not best understood as manually copying every record into a second, separate set of logs. Identify the actual connector, destination, and table used by the configured collection path.

Why Event Viewer remains useful

A missing query result has several possible causes. The event may never have been generated, auditing may not include it, collection may exclude it, delivery may have failed, or the query may be looking in the wrong place. Locating a known event at the source separates generation from transport and query problems.

Validate each boundary

  1. Confirm the event exists on the intended host and record its timestamp and identifier.
  2. Check agent health and the machine's association with the intended collection rule.
  3. Confirm that the rule collects the event channel or selection required by the investigation.
  4. Verify the destination workspace and table.
  5. Check the query's time range, filters, and ingestion delay.

For the Windows Security Events via AMA connector, SecurityEvent is a relevant table. Other collection choices can use different tables; a copied query must match the deployed pipeline.

Keep the evidence portable

Record which source, rule, destination, and query were checked. A functioning dashboard demonstrates the final view. A traceable test event demonstrates that the intended collection path works.

CLOSE THE NOTES. MAKE THE CONNECTION.

Recall check

A Sentinel query returns no failed logons. Does that prove no failed logons occurred?

Reveal the reasoning

No. First verify source events, collection scope and health, destination table, time window, and filters. An empty result describes the query result, not necessarily the underlying activity.
